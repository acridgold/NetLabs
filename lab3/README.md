# GeoBrief: погода и интересные места рядом

Приложение на Kotlin с графическим интерфейсом (Swing, своя тёмная тема). Вводите название места, выбираете вариант из
списка и получаете:

- **Локации** (GraphHopper): пронумерованный список с названием, адресом и типом объекта OSM на русском (`bus_stop` →
  «Автобусная остановка», `square` → «Площадь»), координаты. Словарь тегов: `ui/OsmTags.kt`.
- **Прогноз погоды** (MET Norway: это прогноз на время, указанное в карточке, а не измерение): температура, **ощущаемая
  температура**, ветер, влажность, **давление в мм рт. ст.**, состояние неба. MET Norway ощущаемую температуру не
  отдаёт, она считается по формуле Австралийского бюро метеорологии (температура, влажность, ветер, в тени).
- **Интересные места** (Википедия): пронумерованные карточки с названием, расстоянием от точки, кратким описанием и
  картинкой. Клик по карточке раскрывает полное описание (вводный раздел статьи), крупную картинку и кнопку «Открыть в
  Википедии»; крестик сворачивает карточку.

Все HTTP-вызовы асинхронные (`HttpClient.sendAsync` + `CompletableFuture`), независимые запросы идут параллельно,
зависимые собраны в цепочку без блокировок, результат собирается в один объект `Report` и выводится целиком.

## API

| Роль                | API                                                                                                           | Константа в `Config` |
|---------------------|---------------------------------------------------------------------------------------------------------------|----------------------|
| Поиск локаций       | [GraphHopper Geocoding](https://docs.graphhopper.com/#operation/getGeocode) (нужен ключ)                      | `GEOCODING_URL`      |
| Погода              | [MET Norway Locationforecast 2.0](https://api.met.no/weatherapi/locationforecast/2.0/documentation)           | `WEATHER_URL`        |
| Места рядом         | [Wikipedia GeoData](https://www.mediawiki.org/wiki/Extension:GeoData#API) (`list=geosearch`)                  | `PLACES_URL`         |
| Описание и картинка | [Wikipedia TextExtracts + PageImages](https://www.mediawiki.org/wiki/Extension:TextExtracts#API) по id статьи | `DESCRIPTION_URL`    |

## Запуск

Нужны JDK 17+ и Gradle (или IntelliJ IDEA: откройте папку проекта, зелёная стрелка у `fun main()` в `Main.kt`).

```
./gradlew run        # Windows: gradlew.bat run
```

или `gradle run`, если Gradle установлен.

Ключ GraphHopper не хранится в исходниках и не сохраняется программой. Он берётся из (по порядку):

1. переменной окружения `GRAPHHOPPER_KEY`;
2. файла `secrets.properties` в папке запуска (строка `graphhopper.key=...`; файл в `.gitignore`, не публикуйте его);
3. поля «Ключ GraphHopper» в окне программы (действует до закрытия окна).

В `Config.kt` также: `USER_AGENT` (замените контакт на свой, MET Norway и Wikimedia этого требуют), `MAX_PLACES`,
`DEFAULT_RADIUS_M`, таймауты `REQUEST_TIMEOUT_S` и `IMAGE_TIMEOUT_S`.

## Как пользоваться

1. Введите название (например `Цветной проезд, Новосибирск` или `Красная площадь`) и нажмите Enter или «Найти».
2. Выберите вариант в списке слева (варианты пронумерованы). Под названием показаны адрес и тип объекта.
3. Справа появятся погода и места; нажмите на место, чтобы открыть полное описание, и на крестик, чтобы свернуть. Радиус
   поиска мест (500 м ... 10 км) переключается кнопками, отчёт перезагружается сразу.

## Консоль

Выводится только отладка опроса API: адрес (ключ скрыт), код ответа и время. `OK` пишется только после того, как ответ
получен и успешно обработан; HTTP 200 с некорректным JSON попадёт в лог как `ERROR`.

```
12:01:02.331 [API] OK     GET graphhopper.com/api/1/geocode?q=...&key=*** -> HTTP 200 (412 ms)
12:01:03.020 [API] ERROR  GET api.met.no/weatherapi/locationforecast/2.0/compact?... -> HTTP 403 (95 ms)
12:01:03.400 [API] CANCEL GET ru.wikipedia.org/w/api.php?... -> отменён (310 ms)
```

Ошибки показываются и в интерфейсе: в строке состояния, в карточке прогноза и в карточке каждого места (ошибка описания
и ошибка картинки показываются отдельно от «в Википедии нет описания»).

## Отмена и время ожидания

- Новый поиск или выбор другой локации (и смена радиуса) отменяют предыдущие операции вместе с их сетевыми запросами
  (`RequestScope`, отмена возвращённого `CompletableFuture`).
- Картинки входят в общий отчёт (по ТЗ результаты собираются в один объект), поэтому время ожидания ограничено
  таймаутами: запрос 15 с, картинка 6 с. В худшем случае отчёт ждёт около 36 с (геопоиск, описание, картинка); медленная
  картинка не блокирует отчёт дольше 6 с и показывается как «Картинка не загружена».
- Картинки декодируются в потоке сетевого клиента, не в потоке Swing.

## Структура

```
src/main/kotlin/
├── Main.kt                 точка входа: GuiApp.create().run()
└── APICalling/
    ├── Config.kt           адреса API, User-Agent, таймауты, источник ключа
    ├── Errors.kt           разбор причин ошибок, определение отмены
    ├── model/              Location, Weather, Place, Report, Outcome
    ├── net/                JsonHttpClient (async GET, отмена, лог), RequestScope, ApiLog, Urls
    ├── api/                GeocodingApi, WheatherApi.kt (WeatherApi), PlaceApi.kt (PlacesApi), DescriptionApi
    ├── service/            LocationService (п.2), ReportService (п.4 и 5)
    └── ui/                 GuiApp, MainPanel, LocationList, ReportView, PlaceCard, OsmTags, Theme, Components, Fmt, Settings
```

Зависимости идут сверху вниз: `ui` → `service` → `api` → `net`.

## Возможные ошибки

| Сообщение                            | Причина                                          |
|--------------------------------------|--------------------------------------------------|
| `HTTP 401/403` от graphhopper.com    | неверный ключ или исчерпан лимит запросов        |
| `HTTP 403` от api.met.no / wikipedia | не заменён `USER_AGENT`                          |
| `HTTP 429`                           | слишком частые запросы, подождите                |
| «ничего не нашлось» в местах         | в радиусе нет статей Википедии, увеличьте радиус |
