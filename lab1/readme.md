# multicast-discovery

Приложение обнаруживает другие запущенные копии самого себя в локальной сети
через периодические multicast UDP heartbeat-сообщения и печатает список IP-адресов
"живых" копий при каждом изменении их состава.

## Сборка

```bash
gradle build
# или, если есть только kotlinc:
kotlinc src/main/kotlin/Main.kt -include-runtime -d app.jar
```

## Запуск

```
java -jar app.jar <multicast-адрес> [порт=5000] [сетевой интерфейс]
```

Примеры:

```bash
# IPv4
java -jar app.jar 230.0.0.1 5000

# IPv6 (обычно требуется явно указать интерфейс)
java -jar app.jar ff02::1 5000 eth0
```

Запусти несколько экземпляров (можно на одной машине в разных терминалах,
можно на разных машинах в одной локальной сети) с одинаковым multicast-адресом
и портом — каждый начнёт печатать список IP остальных живых копий.

## Как это работает

- При старте генерируется случайный UUID — идентификатор данной копии.
- Каждую секунду копия рассылает в multicast-группу сообщение вида
  `SELF-DISCOVERY-V1|<uuid>|<timestamp>`.
- При получении такого сообщения от другого UUID узел запоминает
  `(uuid -> IP, время последнего пакета)`.
- Фоновый поток каждые 0.5 сек проверяет, не "протух" ли какой-то узел
  (нет heartbeat дольше 3.5 сек) — если да, узел считается умершим и удаляется.
- Список печатается заново при любом изменении набора живых IP-адресов
  (появление нового узла, исчезновение старого, смена IP у узла).
- Протокол IPv4/IPv6 определяется автоматически по типу переданного адреса
  (`Inet4Address` / `Inet6Address`); для IPv6 join происходит через конкретный
  сетевой интерфейс, как того требует Java API для multicast в IPv6.
