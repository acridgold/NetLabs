# socks-proxy

Учебный SOCKS5-прокси (подмножество RFC 1928) на Kotlin: один тред, неблокирующие
сокеты (`java.nio`), один `Selector`, неблокирующий DNS-резолвинг по UDP (dnsjava).

## Что поддерживается

| Возможность | Статус |
|---|---|
| Команда `CONNECT` (0x01) | да |
| Аутентификация `0x00` (NO AUTH) | да; если клиент её не предложил — ответ `0xFF` и закрытие |
| `ATYP = 0x01` (IPv4) | да |
| `ATYP = 0x03` (доменное имя) | да, резолв через UDP на DNS-сервер |
| `ATYP = 0x04` (IPv6) | нет → `REP = 0x08` |
| `BIND`, `UDP ASSOCIATE` | нет → `REP = 0x07` |
| GSSAPI, USERNAME/PASSWORD | нет |

## Требования

- JDK 22 (если его нет, Gradle скачает сам через foojay toolchain resolver)
- Gradle 8.10+ (JDK 22 требует достаточно свежий Gradle)
- Kotlin 2.1.10 (указан в `build.gradle.kts`; в Kotlin нет версии «2.10», я взял 2.1.10 —
  если нужна другая, поменяйте одну строку `kotlin("jvm") version "..."`)

## Сборка и запуск

Если в проекте ещё нет Gradle Wrapper, создайте его (нужен установленный Gradle):

```bash
gradle wrapper --gradle-version 8.12
```

Запуск напрямую через Gradle:

```bash
# DNS-резолвер из системных настроек, UDP-порт 53
./gradlew run --args="1080"

# явный DNS-резолвер
./gradlew run --args="1080 1.1.1.1:53"
```

Сборка дистрибутива и запуск скриптом:

```bash
./gradlew installDist
build/install/socks-proxy/bin/socks-proxy 1080
build/install/socks-proxy/bin/socks-proxy 1080 8.8.8.8:53
```

Аргументы:

```
socks-proxy <port> [dns_ipv4:port] [--ui-port=N | --no-ui]
```

- `port` — порт, на котором прокси слушает клиентов (обязательный).
- `--ui-port=N` — порт веб-панели администратора (по умолчанию `8081`), `--no-ui` — выключить панель.
- `dns_ipv4:port` — необязательный DNS-резолвер, например `1.1.1.1:53`. Без него берётся
  первый системный DNS-сервер (через dnsjava `ResolverConfig`) и порт 53.

> Прокси слушает на всех интерфейсах и не требует аутентификации. Не открывайте
> порт в интернет — это будет открытый прокси.

## Проверка

### curl

```bash
# домен резолвит прокси (ATYP=0x03)
curl -v --socks5-hostname 127.0.0.1:1080 https://example.com

# адрес резолвит сам curl, прокси получает IPv4 (ATYP=0x01)
curl -v --socks5 127.0.0.1:1080 http://93.184.216.34 -H "Host: example.com"
```

### Браузер

**Firefox:** Настройки → Параметры сети → Настроить → Ручная настройка прокси →
SOCKS-узел `127.0.0.1`, порт `1080`, SOCKS v5, включить
**«Proxy DNS when using SOCKS v5»** (иначе Firefox резолвит сам и DNS прокси не проверяется).

**Chrome / Chromium:**

```bash
google-chrome-stable --proxy-server="socks5://127.0.0.1:1080"
```

Для проверки скорости и корректности откройте DevTools → вкладка Network и сравните
загрузку контента-богатых сайтов с прокси и без.

### Проверка DNS-таймаутов и повторов

Укажите заведомо недоступный резолвер:

```bash
./gradlew run --args="1080 10.255.255.1:53"
curl -v --socks5-hostname 127.0.0.1:1080 http://example.com
```

Прокси отправит запрос 3 раза (через 0, 2 и 4 секунды), затем через ~6 секунд вернёт
клиенту `REP = 0x04` (Host unreachable) и закроет соединение. Остальные клиенты в это
время обслуживаются как обычно.

## Архитектура

Код разбит на слои с односторонними зависимостями: верхние знают о нижних, но не наоборот.

| Пакет | Ответственность |
|---|---|
| `eventloop` | Реактор: один `Selector` + очередь таймеров. Единственный блокирующий вызов — `select(timeout)`. Ничего не знает про SOCKS и DNS |
| `protocol` | Разбор и сборка сообщений SOCKS5 (`Socks5Codec`). Чистые функции над `ByteBuffer`, без сокетов, поэтому покрыты юнит-тестами |
| `dns` | Интерфейс `Resolver` и реализация `UdpDnsResolver` (один UDP-сокет, повторы по таймеру). dnsjava изолирован в `DnsCodec` |
| `net` | `Connector` — неблокирующее подключение к цели с таймаутом и маппингом ошибок в `ReplyCode` |
| `proxy` | `ProxyServer` (корень композиции), `Acceptor`, `Session` (координатор фаз), `ClientHandshake` (клиентская часть SOCKS5), `Relay` (двунаправленная пересылка) |
| `clients` | `ClientRegistry`: активные соединения, накопленный трафик и баны по клиентам. Знает о сессиях только через интерфейс `TrackedConnection` |
| `admin` | `AdminServer` — веб-панель на том же цикле событий (без доп. потоков), `Json` — минимальный JSON-писатель |
| `config`, `cli`, `util` | Конфигурация, разбор аргументов, логирование и мелкие утилиты |

### Жизненный цикл соединения

- **`Session`** владеет сокетами и таймерами, но ничего не парсит и не пересылает.
- **`ClientHandshake`** сообщает о результатах через `Listener` и не знает ни про DNS, ни про подключение.
- **`Relay`** получает готовые каналы и начальные данные, подменяет обработчики на ключах селектора (`key.attach`) и живёт самостоятельно.
- **Асинхронность без реентерабельности.** `Resolver` и `Connector` всегда доставляют результат из цикла событий, а не внутри вызова `resolve()` / `connect()`. Так вызывающий код успевает сохранить возвращённый `Cancellable`.

### Соответствие требованиям задания

- **Один тред, неблокирующие сокеты.** Всё работает в потоке `EventLoop.run()`; других потоков нет.
- **Нет активного ожидания.** `OP_READ` включается только при наличии места в буфере, `OP_WRITE` — только при наличии данных для отправки, `OP_CONNECT` — только пока идёт подключение. После чтения данные сразу пробуют записаться в парный сокет, что экономит круг селектора.
- **Память на клиента ограничена.** Два буфера по 32 КиБ в `Relay` (`ProxyConfig.bufferSize`) и два по 4 КиБ в `ClientHandshake`. Полный буфер отключает чтение из источника.
- **Двунаправленная передача и аккуратное закрытие.** После EOF с одной стороны прокси дожидается отправки буфера, делает `shutdownOutput()` на противоположной стороне и продолжает пересылать обратное направление. Сессия закрывается, когда закрыты оба направления.
- **DNS.** Один неблокирующий `DatagramChannel` в селекторе; A-запрос со случайным ID, ответ сопоставляется по ID и вопросу. Таймаут попытки 2 с, всего 3 попытки, затем клиент получает `REP=0x04`. Усечённый ответ (TC=1) без A-записи считается ошибкой; TCP-fallback не реализован. Если в усечённом ответе адрес есть, он используется.
- **Тайм-ауты.** Рукопожатие — 30 с, подключение к цели — 15 с, доставка ответа об ошибке — 5 с. В режиме релея таймаута нет, чтобы не рвать долгоживущие соединения. Все значения в `ProxyConfig`.

## Админ-панель

После запуска доступна на **http://127.0.0.1:8081/** (порт меняется через `--ui-port=N`, отключается через `--no-ui`).
Страница обновляется раз в секунду.

- **Клиенты слева:** UID, статус, число активных и всего соединений, трафик (`↑` от клиента, `↓` к клиенту), текущая скорость и список активных соединений с адресом цели.
- **Панель справа:** выбранный клиент и большая красная кнопка **БАН** (повёрнута на 45°). Клик по карточке выбирает клиента.
- **БАН** после подтверждения закрывает все соединения клиента и отклоняет его новые подключения. Забаненный клиент остаётся в списке, у него появляется кнопка «РАЗБАНИТЬ».

**UID — это IP-адрес клиента**: в SOCKS без аутентификации другого идентификатора нет. Если несколько человек сидят за одним NAT, у них общий UID и банятся они вместе. Баны хранятся в памяти и сбрасываются при перезапуске.

Бан выделен в журнале (stdout), в терминале — белым по красному:

```
2026-11-10 12:00:00 !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
2026-11-10 12:00:00 !  ЧЕРТ ЗАБАНЕН: 192.168.1.5  (закрыто соединений: 3)  !
2026-11-10 12:00:00 !!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
2026-11-10 12:00:00 192.168.1.5:54321 -> example.com:443 CLOSED [ЗАБАНЕН] up=1834B down=52311B time=6s
2026-11-10 12:00:03 192.168.1.5 BLOCKED: клиент забанен (отклонено подключений: 12)
```

Повторные попытки забаненного клиента логируются не чаще раза в 5 секунд, чтобы не заглушить строку бана.

**Безопасность панели.** Панель не имеет аутентификации и слушает только `127.0.0.1`. Для доступа с другой машины используйте SSH-туннель
(`ssh -L 8081:127.0.0.1:8081 user@server`). Дополнительно проверяется заголовок `Host`, для `POST` нужен заголовок `X-Admin`
(защита от запросов с чужих страниц), а имена хостов из запросов клиентов выводятся через `textContent`, а не `innerHTML`.

## Логирование

Журнал доступа пишется в **stdout**, служебные сообщения и ошибки (`[INFO]`, `[WARN]`) — в **stderr**.
Каждая строка начинается со времени. На соединение приходится одна строка при открытии
и одна при закрытии:

```
2026-11-09 12:00:01 127.0.0.1:54321 -> example.com:443 [93.184.216.34] OK
2026-11-09 12:00:07 127.0.0.1:54321 -> example.com:443 CLOSED up=1834B down=52311B time=6s
2026-11-09 12:00:09 127.0.0.1:54322 -> no-such-host.invalid:80 FAIL HOST_UNREACHABLE (DNS: rcode=NXDOMAIN, A-записей нет)
2026-11-09 12:00:12 127.0.0.1:54323 -> 10.0.0.5:22 FAIL CONNECTION_REFUSED (java.net.ConnectException: Connection refused)
```

- `клиент -> цель` — адрес клиента и то, что он запросил (доменное имя или IP с портом).
- В квадратных скобках — IP, к которому прокси реально подключился.
- `OK` — соединение установлено, `FAIL` — отказ с указанием кода `REP` и причины.
- `CLOSED` — итог: сколько байт ушло от клиента на сервер (`up`) и обратно (`down`) и сколько секунд длилась сессия.

Сохранить журнал доступа в файл, ошибки оставить в консоли:

```bash
build/install/socks-proxy/bin/socks-proxy 1080 > access.log
```

Смотреть журнал в реальном времени: `tail -f access.log`.

> Журнал содержит историю посещённых сайтов, то есть персональные данные.
> Если прокси пользуется кто-то кроме вас, ограничьте доступ к файлу и предупредите пользователей.

## Коды ответов при ошибках

| Ситуация | REP |
|---|---|
| DNS не ответил за 3 попытки / NXDOMAIN / ответ без A-записи | `0x04` |
| Соединение отклонено целевым хостом | `0x05` |
| Сеть недоступна | `0x03` |
| Нет маршрута / таймаут подключения | `0x04` |
| Команда не `CONNECT` | `0x07` |
| IPv6 или неизвестный ATYP | `0x08` |
| Прочие ошибки | `0x01` |
