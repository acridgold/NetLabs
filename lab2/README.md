# Передача файла по TCP

## Сборка и запуск
```bash
docker build -t lab2 .

# сервер (файлы попадут в ./uploads); третий аргумент — число рабочих потоков, по умолчанию 32
mkdir -p uploads
docker run --rm -p 5267:5267 -v "$PWD/uploads:/data/uploads" --name ft-server lab2 server 5267

# клиент (отправляем файл ./big.iso на сервер на хосте)
docker run --rm -v "$PWD:/files:ro" --network host lab2 client /files/big.iso 127.0.0.1 5267
```
Через compose: `docker compose -p lab2 up --build client` (файл задаётся переменной `FILE` в `.env`).

Без Docker: `gradle installDist && build/install/lab2/bin/lab2 server 5267`.

Параметры: `server [port] [maxClients]` и `client <file> [host] [port]`. Порт допустим в диапазоне 1..65535.

### Скрипт
В репозитории лежит скрипт `scripts/RunMe.sh`, запускающий автоматические интеграционные тесты для детальной проверки клиент-серверного взаимодействия.
Для запуска на вашей машине требуется изменить целевые пути и пересобрать командой `./gradle installDist`!

## Протокол
Числа передаются в порядке big-endian. Поверх TCP обмен идёт в таком порядке:

1. Клиент -> сервер: **заголовок**.
2. Сервер -> клиент: байт **READY** (2). Пока клиент его не получил, данные отправлять нельзя.
3. Клиент -> сервер: ровно `размер` байт содержимого.
4. Сервер -> клиент: байт **OK** (1) или **FAIL** (0), после чего сервер закрывает соединение.

Если все потоки сервера и очередь ожидания заняты, вместо READY сервер отправляет FAIL и закрывает соединение.

### Заголовок

| Смещение | Размер | Поле |
|---|---|---|
| 0 | 6 байт | сигнатура `ALOOO` = `4E 53 4B 50 36 37` («NSKP67») |
| 6 | 4 байта (int) | длина имени `N` в байтах, 1..4096 |
| 10 | `N` байт | имя файла в UTF-8 (некорректный UTF-8 отклоняется, символы не подменяются) |
| 10+N | 8 байт (long) | размер файла в байтах, 0..2^40 |

Заголовок занимает `18 + N` байт.

### Ответы сервера (1 байт)

| Код | Значение |
|---|---|
| 2 (READY) | заголовок принят, можно отправлять данные |
| 1 (OK) | файл получен полностью, размер совпал |
| 0 (FAIL) | передача отклонена или не удалась |

Сервер считает передачу успешной только после того, как OK отправлен клиенту.

## Поведение сервера
* Файлы сохраняются только в `uploads/`; при совпадении имён добавляется суффикс ` (1)`, ` (2)`.
* Приём ведёт пул из `maxClients` потоков. Главный поток только вызывает `accept()`, поэтому новые соединения принимаются всегда: при занятых потоках клиент ждёт в очереди (до 64), при переполнении очереди получает FAIL.
* Любая ошибка при обработке клиента (в том числе ошибка файловой системы: нет места, нет прав, сбой записи) приводит к ответу FAIL, закрытию только этого соединения и удалению недокачанного файла. Остальные клиенты не затрагиваются.
* Таймаут чтения 30 секунд освобождает поток, занятый зависшим клиентом.
* Ошибки `accept()` повторяются с паузой (от 0,1 до 2 с). После 10 ошибок подряд сервер корректно останавливается с кодом 1.
* Остановка (SIGTERM, Ctrl+C, `docker stop`): сервер перестаёт принимать соединения, ждёт активные передачи 3 секунды, затем рвёт оставшиеся. Недокачанные файлы удаляются, клиентам из очереди отправляется FAIL.
* Раз в 3 секунды для каждого активного клиента выводится мгновенная и средняя скорость.

## Клиент
* Таймаут чтения 60 секунд. Таймаут записи 30 секунд: у блокирующего сокета его нет, поэтому за временем записи следит отдельный поток и закрывает сокет, если сервер перестал принимать данные.
* Если запись оборвалась, клиент пробует прочитать причину: ответ FAIL от сервера выводится в сообщении об ошибке.
